# Homework 5 — Data from the Web

## Overview

In HW5 the question and the data are yours. You ask a question, **collect the data yourself
from an open API**, and go through the whole cycle. The focus is the week 5 material: a fetch
script that downloads politely and **caches the raw responses**, a record of where every file
came from and under which licence, and a clear account of **how the data were generated**: who
or what is in them, and who or what is not.

This is also a rehearsal for the project, where you will choose data and a question in the same
way.

Read [week 5](/lectures/week-5) first. It goes through every step on the Nobel Prize API.

## Learning goals

- Turn an interest into a question that an open dataset can answer.
- Request data from an API, handle paging, and turn JSON (or CSV) into a tidy table.
- Cache raw responses, so the report renders without the internet.
- Record provenance and licence, and keep any API key out of Git.
- Write limitations that come from how the data were produced and selected.

## The question

Your own. A good HW5 question:

- says **what** is measured, **where or for whom**, and **compared with what**
  ([week 1](/lectures/week-1#asking-a-question-data-can-answer));
- can be answered with **one to a few hundred requests at most**, usually far fewer;
- needs some numbers you have to compute, not one value you could read off a web page.

Keep it modest: a clear answer to a small question is better than a vague answer to a big one.
Don't reuse the week 5 question (the age of physics laureates).

## The data

Use an **open API** that allows the use you make of it. You don't have to choose from this list,
but every API on it worked without problems on 6 November 2026:

| API | What it has | Key? | Licence |
|---|---|---|---|
| [SCB, PxWebApi 2](https://www.scb.se/en/services/open-data-api/) | official Swedish statistics: population, income, education, housing… | no (at most 30 requests per 10 s) | CC0 |
| [SMHI Open Data](https://opendata.smhi.se/) | weather observations per station: temperature, precipitation, snow depth, wind | no | CC BY 4.0 |
| [Kolada](https://api.kolada.se/v3/docs) | key figures for every municipality and region: schools, care, economy | no | see the site |
| [Riksbanken, SWEA](https://developer.api.riksbank.se/) | interest rates and exchange rates, daily | no, for a few requests; register for more | see the site |
| [World Bank Indicators](https://datahelpdesk.worldbank.org/knowledgebase/articles/889392) | thousands of indicators per country and year | no | CC BY 4.0 |
| [Nobel Prize API](https://www.nobelprize.org/about/developer-zone-2/) | prizes and laureates since 1901 | no | CC0 |
| [Trafiklab](https://www.trafiklab.se/) | Swedish public transport: stops, timetables, departures | **yes**, free on registration | see each API |

Kolada's old version 2 now answers *410 Gone*; use version 3, as in the example below. SCB's older
v1 API still answers, but new tables appear in v2.

### Four questions to start from

If you can't think of a question, start from one of these and make it your own: choose the
places, the years and the comparison yourself.

1. **Have small municipalities shrunk while large ones grew?** SCB, table TAB628, population per
   municipality in 2000 and 2025, in one request:
   `https://statistikdatabasen.scb.se/api/v2/tables/TAB628/data?lang=en&valueCodes[Region]=*&valueCodes[Kon]=1+2&valueCodes[ContentsCode]=BE0101U2&valueCodes[Tid]=2000,2025&outputFormat=csv`
   Keep the four-digit codes (municipalities) and read them as text.
2. **Has Umeå fewer days with snow on the ground than in the 1960s and 70s?** SMHI, parameter 8
   (snow depth, daily), station 140490 (Umeå-Röbäcksdalen):
   `https://opendata-download-metobs.smhi.se/api/version/1.0/parameter/8/station/140490/period/corrected-archive/data.csv`
   The header lines describe the station; note that there are no measurements from 1987 to 1996.
3. **Do countries with higher income have longer lives, and has the gap changed since 2000?**
   World Bank, indicators `NY.GDP.PCAP.CD` (GDP per person) and `SP.DYN.LE00.IN` (life
   expectancy), with paging:
   `https://api.worldbank.org/v2/country/all/indicator/SP.DYN.LE00.IN?format=json&date=2023&per_page=100&page=1`
   The first element of the answer says how many `pages` there are. The list mixes countries with
   regions and income groups (“Africa Eastern and Southern”, “High income”): decide which rows
   are countries.
4. **Is the krona more volatile against the euro since 2020 than in the 2010s?** Riksbanken,
   series `SEKEURPMI` (daily SEK per EUR):
   `https://api.riksbank.se/swea/v1/Observations/SEKEURPMI/2010-01-01/2026-10-31`

Kolada, version 3, works the same way: `https://api.kolada.se/v3/data/kpi/N01951/year/2023`
gives indicator N01951 (population) for every municipality, but also for regions and over three
thousand groups of municipalities (codes starting with `G`). Add `per_page=1000` and it comes in
pages, each pointing to the next with `next_url`.

## Tasks

Follow [How we work](/guide#hand-in-an-assignment): update `main`, and make a branch called
`hw5` from it. Add the packages you need: Python `uv add requests` (and `lxml` if you read HTML);
R `renv::install("httr2")`, then `renv::snapshot()` (`jsonlite` is already in the template).
Then:

0. **Set up the folder.** Your name in the header of `hw5/report.qmd`. Write a fetch script,
   `hw5/fetch.py` or `hw5/fetch.R`, that:
   - downloads everything your report needs and saves each response **unchanged** in
     `hw5/data/raw/`;
   - skips a file that already exists, so running it again sends no requests;
   - waits at least one second between requests, and sends a User-Agent that names the course
     (not your e-mail address);
   - handles paging, if your API pages its results.

   Run it from the repository root (`uv run python hw5/fetch.py` or `Rscript hw5/fetch.R`), so
   write its paths as `hw5/data/raw/…`. Commit the script and the files it saved. In
   `hw5/data/raw/README.md`, give every file a row with the source, the exact query (URL and
   parameters), the licence and the date you fetched it.
1. **Question** — your question, and why someone might care about the answer.
2. **Data** — which API, who publishes it, and what one row is. Then **how the data were
   generated**: who or what is measured, by whom, and why; who or what is not in the data
   ([who is in the data?](/lectures/week-5#who-is-in-the-data)). If you used a key, say so, and
   say how a reader gets their own.
3. **Cleaning** — read the cached files (never the API) and build a tidy table. Show that it is
   right: the number of rows against what the API said there are, the types, missing values.
   Write down every decision (which rows you keep, how you handle gaps) and why.
4. **Exploration** — at least one figure, with a caption that says what to see, following the
   [checklist for honest plots](/lectures/week-2#honest-plots). Describe what you see.
5. **Analysis** — answer the question with a method that fits it: a comparison of groups or
   periods with a **95% confidence interval**, a correlation, or a trend
   ([statistics sections 4–6](/statistics#_4-how-sure-are-you-standard-errors-and-confidence-intervals)).
   If your data are a whole population, say whether an interval still makes sense, and why
   ([as on the week 5 page](/lectures/week-5#answering-the-question)).
6. **Conclusions & limitations** — the answer in the form of
   [statistics section 9](/statistics#_9-writing-it-up): the estimate, its uncertainty, and what
   it can't tell you. At least one limitation must come from **how the data were produced or
   selected**: who is missing, what changed in how it was measured, what the API leaves out.
7. **How to reproduce** — two parts: how to fetch the data again (the command for the fetch
   script, and any key it needs), and how to render the report from the cached files.

Every number in your text should come from the code
([inline code](/lectures/week-2#tables-and-numbers-in-a-report)).

**The report must not call the internet.** The check on GitHub renders it from the files in
`hw5/data/raw/` only. If the report needs the API to render, the check may still be green today,
but it is not reproducible, and it loses points.

**Keys.** If your API needs a key, keep it in a file `.env` at the repository root, add the line
`.env` to `.gitignore` and commit that first, as in [week 5](/lectures/week-5#api-keys). A key in a
commit is a key you must revoke.

Render with `uv run quarto render hw5/report.qmd` (Python) or `quarto render hw5/report.qmd`
(R), read `hw5/report.md`, and commit everything in `hw5/`. Change nothing outside `hw5/`, except
the lockfile if you added a package and `.gitignore` if you use a key.

## Hand in

1. Push your branch `hw5` and open a pull request **from `hw5` into `main`** titled **`HW5`**,
   by the deadline in the [schedule](/homework/#schedule). Opening the pull request is the
   hand-in. ([How](/guide#hand-in-an-assignment))
2. In the pull request description, write your question and your answer in two or three lines,
   name the API, and list the decisions a reviewer should look at.
3. Make sure the check is green. If it is red, see [When the check is red](/guide#when-the-check-is-red).
4. Don’t merge it yourself; we merge it when it is accepted.

Pushing straight to `main` is not a hand-in: only the pull request counts.

## After the review

Your own pull request gets a review by Thursday. You can push improvements until **Friday 23:59**;
we grade the pull request as it stands then.

## Peer review

After the deadline you get access to a classmate’s repository (until Friday morning). Review their
pull request by Thursday 23:59, as described in [Review a pull request](/guide#review-a-pull-request).
Comment on specific lines in **Files changed**. For HW5, check especially:

- Is the question one the data can answer? Would you sharpen it, and how?
- Does the fetch script cache every response in `data/raw/`, skip files it already has, pause
  between requests, and handle paging? Does the report read only the cached files?
- Does `data/raw/README.md` give the source, query, licence and date for every file?
- Is there a key, a token or a password anywhere in the code or the history? (If so, tell them
  at once.)
- Does the cleaning show that nothing was lost: rows against the API's count, types, missing values?
- Is there a limitation about how the data were generated or selected, and is it a real one for
  this question?
- One highlight and one concrete suggestion, pointing to a line or a figure.

## Scoring

HW5 is scored 0–100, and you need 65 to pass. Late hand-ins and the final deadline: see
[Assignments](/homework/). We look for:

- a clear question of your own, and all seven sections, each doing its job, with a green check;
- a polite fetch script that caches raw responses, and a report that renders from the cache;
- provenance and licence for every file, and no key in the repository;
- cleaning that is checked and written down, an honest figure, and an analysis with its
  uncertainty;
- limitations that come from how the data were produced, and conclusions that match the evidence;
- a specific, constructive peer review.

## Allowed tools

Use any packages you like; add them with `uv add` or `renv::install()` + `renv::snapshot()` so
the check can install them too. If you use AI assistants or other sources, say what you used and
how. Scrape a web page only if no API or download has the data, and only if its terms and
`robots.txt` allow it ([when not to scrape](/lectures/week-5#when-not-to-scrape)).
